快速开始

用 scoop-install 安装所需版本和目标，再运行第一个程序。安装器在独立的 scoop-lang/scoop-install 仓库维护。

安装工具链

默认安装宿主命令、一个本机目标的预编译基础库，以及支持 LSP 源码导航的 sources。GUI 库、其他 target 和上游 vendor 源码可按需添加。工具链自带 LLVM、LLDB 与调试器所需的 Python；安装器自身不要求 Python、Rust、Cargo 或系统 tar。

宿主默认 target可追加 target 与构建要求
Apple Silicon macOSaarch64-apple-darwin可追加 x86_64-apple-darwin；应用构建需 Xcode 或 Command Line Tools 与 macOS SDK。当前发行基线 macOS 27.0.1。
x86-64 GNU/Linuxx86_64-unknown-linux-gnu可追加 x86_64-unknown-linux-musl；需 GCC、GNU ld 与开发文件，musl 目标另需 musl-gcc。当前基线 glibc 2.43／musl 1.2.5；musl 不提供 GUI 组件。
x64 Windowsx86_64-pc-windows-msvc-ucrt可追加 x86_64-w64-windows-llvm-mingw-ucrt、x86_64-w64-windows-llvm-mingw-msvcrt，自动安装对应 LLVM-MinGW SDK 数据。默认 MSVC 目标需本机 C++ Build Tools 与 Windows SDK；当前发行基线 build 10.0.26300。

可安装组合与系统要求以该版本的 manifest 和发行配置为准。GNU 宿主程序不保证在纯 musl 系统运行；scoop.asyncio 的 Linux 程序另需内核 6.1 及可用的 io_uring。

Windows 上的主命令是 sco

本站的 scoop … 命令在 Windows 上写作 sco …，例如 sco run hello.scoop。安装器仍叫 scoop-install，其他工具和 SCOOP_* 环境变量也保持原名。

macOS／Linux 一键安装

curl -fsSL https://scoop-lang.org/install.sh | sh
# Linux：只安装 musl 目标，省略 GNU 默认目标
curl -fsSL https://scoop-lang.org/install.sh | sh -s -- --target x86_64-unknown-linux-musl
# 安装一个已发布的精确版本
curl -fsSL https://scoop-lang.org/install.sh | sh -s -- 0.0.0-dev.20261113

脚本下载本机的 scoop-install 并调用 toolchain install。默认安装在 ~/.scoop，将 bin 加入 Bash、Zsh、Fish 或 POSIX shell 配置。完成后打开新终端，或运行 export PATH="$HOME/.scoop/bin:$PATH"。用 --home DIR 或 SCOOP_HOME 指定其他目录；SCOOP_NO_MODIFY_PATH=1 可跳过持久化 PATH。

Windows 一键安装

irm https://scoop-lang.org/install.ps1 | iex
# 只安装 MinGW UCRT 目标
& ([scriptblock]::Create((irm https://scoop-lang.org/install.ps1))) --target x86_64-w64-windows-llvm-mingw-ucrt

支持 Windows PowerShell 5.1 和 PowerShell 7。默认安装在 %USERPROFILE%\.scoop，更新用户 PATH 和当前会话；设置 $env:SCOOP_NO_MODIFY_PATH = '1' 可跳过用户 PATH 修改。脚本错误会保留交互窗口，失败状态记录在 $LASTEXITCODE。

直接使用安装器

安装器和工具链组件均从 release.scoop-lang.org 下载。当前安装器版本为 0.1.0，也可以直接下载对应宿主的可执行文件：

宿主安装器下载
Apple Silicon macOSscoop-install（ARM64）
x86-64 GNU/Linuxscoop-install（x86-64）
x64 Windowsscoop-install.exe（x64）

SHA-256 校验清单。将下载的文件命名为 scoop-install（Windows 为 scoop-install.exe；macOS／Linux 需执行 chmod +x scoop-install），运行：

./scoop-install toolchain install latest

手动安装后，将管理目录的 bin 加入 PATH（默认 ~/.scoop/bin，Windows 为 %USERPROFILE%\.scoop\bin），再查询和管理工具链：

scoop-install show
scoop-install toolchain list
scoop-install target list
scoop-install component list

默认只选择本机 target；显式 --target 列表替代默认列表，可以重复传入或用逗号分隔。安装目标后仍须在编译时用 --target 选择它。以下示例适用于 macOS：

scoop-install target add x86_64-apple-darwin
scoop-install component add gui --target aarch64-apple-darwin
scoop-install component add vendor
scoop-install component remove vendor
scoop-install target remove x86_64-apple-darwin

sources 包含 Scoop 自有 Cone、胶水、公开头文件和资源，默认保留用于 FFI 与 LSP；vendor 包含上游源码及编译补丁，重建上游库时才需要。每个 target 的 base 包提供预编译系统库、native 库与 runtime；GUI 组件依赖同版本同目标的 base。

安装后生成已选目标的离线 API 文档，不重建系统库。--skip-docs 可暂缓生成，之后用 scoop-install docs 补齐；文档生成失败时工具链仍可使用，按提示重试。离线或私有分发可用 toolchain install --manifest PATH_OR_URL；镜像根地址通过 SCOOP_DIST_SERVER 配置。

版本与项目选择

scoop-install toolchain install 0.0.0-dev.20261113
scoop-install default 0.0.0-dev.20261113
scoop +0.0.0-dev.20261113 --version
scoop-install update

update 保留当前默认版本已选的 targets、各目标 GUI 和 vendor，完整安装成功后切换默认版本，旧版本继续保留。确认不再需要时用 toolchain remove VERSION 删除；删除当前默认版本前先选择另一个默认版本。构建缓存按工具链发行身份隔离，切换版本不需要手动 clean。

在项目或其父目录放置 scoop-toolchain.toml：

[toolchain]
version = "0.0.0-dev.20261113"
targets = ["aarch64-apple-darwin"]

选择优先级为命令行 +VERSION、SCOOP_TOOLCHAIN、最近的项目配置、全局 default。项目缺少所需版本或 target 时给出安装命令，不在编译或编辑时自动下载。VS Code 扩展从工作区目录启动语言服务，多工作区可各自固定版本。

安装目录：

~/.scoop/
  bin/                       scoop-install 与 Scoop 命令代理
  settings.toml              默认版本
  downloads/                 已下载的组件归档
  packages/                  各版本共享的包管理器源码缓存
  commands/                  用户外部子命令
  toolchains/<version>-<host>/
    bin/                     该版本的实际工具
    lib/<target>/            所选目标的预编译库与 runtime
    src/、include/、native/  自有 Cone、头文件、胶水和资源
    vendor/                  按需安装的上游源码与补丁
    libexec/、tooling/        LLVM／LLDB／Python 与编辑器工具
    docs/<target>/           安装后生成的 API 文档

代理启动真实版本中的程序，工具据自身位置定位 sysroot；显式 --sysroot 或 SCOOP_SYSROOT 仍可覆盖资源位置。

从源码构建

构建依赖与流程见脚本说明。python3 scripts/package_toolchain.py --download-dir /path/to/downloads --jobs 6 可在不同工作目录间复用上游下载，输出组件归档及 manifest。工具链、安装器和官网分别在独立仓库维护。

第一个程序

新建 hello.scoop：

{{example hello nooutput}}

直接运行这个文件：

$ scoop run hello.scoop --release
Hello, Scoop!

单文件程序默认依赖 scoop.core 与 scoop.std，不读取旁边的 Cone.toml；编译产物放在当前目录的 target/ 下。--release 启用优化。建议总是用 -- 分隔 Scoop 选项与程序参数，例如 scoop run hello.scoop --release -- Ada；程序的 args[0L] 是启动路径，用户参数从 args[1L] 开始。

单文件依赖

单文件程序在文件头部用 //! dep: 声明额外依赖的精确坐标，从预编译产物中查找，例如使用 JSON 库。单文件入口不参与 PM 的版本求解；需要 Git/registry、源码依赖或 workspace 时使用 Cone 项目。

{{example json}}

文件首行也可以是 #! 解释器注释，因此 Scoop 文件能直接作为脚本执行：

#!/usr/bin/env -S scoop run --release
fun main() {
    println("I am a script")
}

创建项目

Scoop 的模块、包与发布单元叫做 Cone。用 scoop new 创建一个可执行 Cone：

$ scoop new --group dev.example hello
created hello
$ cd hello
$ scoop run --release
Hello, Scoop!

生成的结构如下：

hello/
  Cone.toml          Cone 清单
  src/main.scoop     生产源码
  tests/basic.scoop  测试源码（只在 scoop test 时编译）
src/main.scoop
package dev.example

fun main() {
    println(greeting())
}

fun greeting(): String = "Hello, Scoop!"
tests/basic.scoop
package dev.example

import scoop.test.*

@Test
private class BasicTests {
    @Test
    fun `greeting is ready`() {
        assertEquals("Hello, Scoop!", greeting())
    }
}
$ scoop test --release
hello
  dev.example.BasicTests [passed]
    greeting is ready (tests/basic.scoop:7:5) passed (4000 ns)
1 containers, 1 tests: 1 passed, 0 failed, 0 ignored, 0 not run

使用 --kind library 创建库 Cone，--no-tests 省略示例测试。

Cone.toml 与依赖

Cone 自身用完整 group:name:version 标识；依赖可以声明版本要求，由独立包管理器解析，再用 Cone.lock 固定精确版本与来源。下面是仅依赖内置库、可以直接使用的清单：

Cone.toml
schema = 1

[cone]
group = "dev.example"
name = "my-app"
version = "0.1.0"
kind = "executable"

[dependencies]
"scoop:scoop.std" = "=0.1.0"
"scoop:scoop.json" = "=0.1.0"

[test-dependencies]
"scoop:scoop.test" = "=0.1.0"

"1.4.0" 和 "^1.4.0" 都表示 >=1.4.0, <2.0.0；"=1.4.0" 才是精确版本。~1.4.2 和比较项交集也可使用；0.x 的兼容范围按首个非零版本段收窄。不能写 latest、通配符或省略版本段。

在 [dependencies] 中还可以按实际来源加入以下条目；示例目录、仓库和 registry 地址须替换成自己的输入：

"dev.example:util" = { version = "0.2.0", path = "../util" }
"org.example:http" = { version = "1.2.0", github = "example/http", tag = "v1.2.0" }
"org.example:json" = { version = "1.4.0", registry = "https://packages.example.org/" }
"org.acme:codec" = { version = "=1.0.0", artifact = "../artifacts/codec.slib" }
  • path 指向另一个源码 Cone，scoop 会一并构建；
  • github/git 指定 Git 来源，branch/tag/rev 选择引用，lock 固定实际 commit；
  • registry 指向静态 HTTP(S) registry；PM 选择版本、下载源码后交给构建工具；
  • artifact 指向预编译的 .slib 产物；
  • 未指定来源的 scoop group 使用 sysroot；其他 group 使用已配置的默认 registry，没有默认值就报错；
  • [test-dependencies] 只参与测试构建，不进入生产产物。

普通构建会自动解析并生成或更新必要的 lock 记录，优先保留相容的已有选择。可以把 Cone.lock 提交到版本库，在 CI 使用 --locked，或在依赖已准备时用 --frozen 同时禁止联网：

$ scoop pm resolve
$ scoop pm deps
$ scoop build --release --locked
$ scoop pm update

Git/registry 源码默认缓存在 ~/.scoop/packages/。多 Cone 项目可以使用 [workspace]，通过 -p group:name 选择成员，或用 scoop build --workspace / scoop test --workspace 处理全部成员；run 必须选中唯一可执行 Cone。规则见包管理规范。维护 registry 的步骤见发布指南；目前已交付消费端，打包与索引维护命令仍属后续计划。

Cone 还可以携带 C/C++ 源码与原生系统库，用于编写 FFI 绑定，详见参考文档的原生互操作一章。

命令速查

命令作用
scoop new <path> --group <g>用固定模板创建可执行或库 Cone
scoop pm <command>管理 workspace、依赖与锁文件；支持 add/remove、resolve/fetch/update、deps 等
scoop build [root]从 Cone 或单个源文件构建可执行文件或库；-o 指定输出，--emit ast|hir|mir|lir|all --dump-dir DIR 导出中间表示
scoop run [root] [args…]构建并运行可执行文件，继承调用者的环境变量和标准输入输出
scoop test构建并运行当前 Cone 的测试
scoop fmt [inputs…]格式化 Cone 或指定源码；--check 只报告格式差异
scoop check [root]完成前端检查，不生成根 Cone 的机器产物；--tests 检查测试用途
scoop doc [roots…]从文档注释生成离线 API 文档站点
scoop link不编译源码，只链接已有产物
scoop clean [root]移除选定 target 目录中的所有 profile 与构建缓存
scoop example [topic]查询离线示例；支持 --list 与 --search
scoop <other>先查找工具链的 commands/，再查共享的 $SCOOP_HOME/commands/ 外部子命令

常用选项：--release（优化构建）、--target <triple>（交叉目标）、--target-dir（输出目录）、-j（并发编译进程数）、--message-format json（机器可读诊断）。

编辑器支持

工具包附带 VS Code 扩展，提供 Tree-sitter 语法高亮、折叠、缩进，以及通过 scoop-lsp 提供的诊断、补全、悬停文档、签名帮助、跳转、引用、重命名和快速修复：

$ scoop-install show  # 查看 Root 所指的工具链目录
$ code --install-extension /path/to/toolchain/tooling/scoop-language-support-*.vsix

扩展会依次查找 scoop.server.path 设置、~/.scoop/bin/scoop-lsp 与 PATH 中的 scoop-lsp。Tree-sitter 语法包（tree-sitter-scoop）也可以单独用于其他支持 Tree-sitter 的编辑器。

编辑器消费已有的锁定依赖，不自动更新版本或下载源码。缺少 lock 或依赖时，在项目目录运行 scoop pm resolve 或 scoop pm fetch，再继续分析。

源码调试

工具包附带 scoop-lldb 与 scoop-lldb-dap（带 scoop- 前缀，可与其他 LLVM 安装共存于 PATH）。在 VS Code 中按 F5 选择 Scoop，或运行 Scoop: Debug Current File，可自动构建并启动调试；也支持调试测试和附加现有进程。

$ scoop build --release --debug-info full

调试文件随程序输出：macOS 使用 .dSYM，Linux 使用 .debug，Windows 使用相邻的 .pdb。debug 构建默认包含完整调试信息，release 默认不包含；异常与 trap 可以显示物理栈及源码位置。当前不提供完整 Scoop 表达式求值或协程逻辑栈，配置方法见调试说明。
