快速开始

安装 Scoop 工具链、运行第一个程序，然后创建一个带测试的项目。本页按当前工具包布局介绍安装、依赖管理与常用命令。

安装工具链

Scoop 的工具包包含编译器、包管理器、链接器、语言服务、调试器、标准库源码、C 运行时和配套原生库，不需要另外安装 LLVM。系统库以预编译的 .slib 随目标库组件包提供，安装后只需用随包工具在本机生成离线 API 文档；编译应用直接使用这些预编译库，不会重新编译系统库。构建应用需要下面列出的系统开发工具。

平台目标说明
macOSaarch64-apple-darwinApple Silicon，当前发行基线 macOS 27.0.1；需 Xcode 或 Command Line Tools、Apple Clang、macOS SDK 与系统 linker
Linuxx86_64-unknown-linux-gnu / x86_64-unknown-linux-muslGNU 宿主包提供两套目标资源；当前基线 glibc 2.43 / musl 1.2.5。需 GCC、GNU ld 与开发文件，构建 musl 程序另需 musl-gcc 和匹配的开发文件
Windowsx86_64-pc-windows-msvc-ucrt（默认）

x86_64-w64-windows-llvm-mingw-msvcrt		Windows 10 x64 及以上，当前发行基线 build 10.0.26300。工具包自带 Clang、LLD、资源编译器和两套 LLVM-MinGW 开发资源；默认的 MSVC UCRT 目标另需本机 C++ Build Tools 与 Windows SDK（不需要完整的 Visual Studio IDE）。使用前先为所选目标执行 post-install

版本基线以随包说明及发行配置为准；GNU 宿主命令不保证在纯 musl 系统运行。使用 scoop.asyncio 的 Linux 程序还要求内核 6.1 及实际可用的 io_uring 能力；这一要求不适用于所有 Scoop 程序。

Windows 上的命令名是 sco

为避免与同名的 Scoop 包管理器冲突，Windows 工具包的主驱动安装为 sco.exe，不提供 scoop.exe 别名。本站所有 scoop … 命令在 Windows 上写作 sco …，例如 sco run hello.scoop、sco pm resolve、sco example --list。其他程序名不变（scoopc.exe、scoop-pm.exe、scoop-lsp.exe 等），环境变量仍是 SCOOP_*。

macOS／Linux 一键安装

curl -fsSL https://scoop-lang.org/install.sh | sh

脚本读取 release.scoop-lang.org/latest.txt 索引，下载适合本机的最新版各组件包，解压到 ~/.scoop，生成默认目标的 API 文档，再把 ~/.scoop/bin 加入 shell 配置。支持 Apple Silicon macOS 和 x86-64 GNU/Linux；Bash、Zsh、Fish 使用各自的配置文件，其他 shell 使用 ~/.profile。完成后打开新终端，或在当前 sh／Bash／Zsh 中执行 export PATH="$HOME/.scoop/bin:$PATH"。

安装脚本用 shell 直接调用随包编译器，不要求另装 Python、Rust、Cargo 或 CMake；调试器所需的配套 Python 仍包含在工具包内。可以用 --release 指定已发布的 release（例如 2026-11-09），并在 -- 后传入 post-install 选项：

curl -fsSL https://scoop-lang.org/install.sh | sh -s -- --release 2026-11-09
curl -fsSL https://scoop-lang.org/install.sh | sh -s -- -- --jobs 2

再次运行可升级到所选版本。工具、系统库、源码、native 库、runtime 和文档目录会被替换；下载缓存、安装构建缓存和用户外部命令保留。升级后需要其他目标的文档时重新执行 post-install。若准备失败，修正报错后重跑 sh ~/.scoop/post-install.sh 即可。

Windows 一键安装

在 PowerShell（Windows PowerShell 5.1 或 PowerShell 7）中运行：

irm https://scoop-lang.org/install.ps1 | iex

脚本读取同一份索引，下载 windows 的全部组件包，用系统自带的 tar.exe 解压到 %USERPROFILE%\.scoop，为默认的 MSVC UCRT 目标生成 API 文档，再把 %USERPROFILE%\.scoop\bin 加入用户 PATH。当前 PowerShell 窗口可以直接使用 sco，其他终端需重新打开。要求 x64 Windows，且系统 tar.exe 支持 xz（tar --version 的输出包含 liblzma）；否则请按下文手动安装。在 cmd 中可运行 powershell -ExecutionPolicy Bypass -c "irm https://scoop-lang.org/install.ps1 | iex"。

指定 release、跳过 PATH 修改或传入 post-install 选项时，把脚本作为脚本块调用：

& ([scriptblock]::Create((irm https://scoop-lang.org/install.ps1))) -Release 2026-11-09
& ([scriptblock]::Create((irm https://scoop-lang.org/install.ps1))) -NoModifyPath -- --all-targets

升级规则与 macOS／Linux 相同。若准备失败，修正报错后重跑 & "$HOME/.scoop/post-install.ps1"。

手动安装

  1. 解压工具包

    打开 latest.txt，下载本平台（macos、linux 或 windows）package 行列出的归档，地址为 https://release.scoop-lang.org/<路径>：

    • bin-<host>：编译器等命令、外部子命令、随包 LLVM／LLDB 工具与调试器 Python，必装；
    • sources：内置 Cone 源码、公开头文件与 vendor 输入，必装；
    • lib-base-<target>：该目标的预编译非 GUI 系统库、native 库与 runtime，每个要使用的目标都需要；
    • lib-gui-<target>：scoop.window、scoop.graphics、scoop.ui 等 GUI 库及 Skia，开发 GUI 程序时与同目标的 lib-base 一起安装；
    • native-<target>：仅 Windows 的两个 LLVM-MinGW 目标，提供该 CRT 的配置头、启动对象与导入库。

    同一 release 的包按相同版本成组安装。各归档顶层直接就是安装根，依次解压到同一目录：

    $ mkdir -p ~/.scoop
$ for f in scoop-*.tar.xz; do tar -xJf "$f" -C ~/.scoop; done
  2. 生成 API 文档 
    sh ~/.scoop/post-install.sh

    post-install 只为已安装的目标生成离线 API 文档，不再构建系统库。默认处理本机目标；用 --target <triple> 处理其他已安装的目标，或用 --all-targets 处理全部已安装的目标。例如 Linux 用户可运行 sh ~/.scoop/post-install.sh --target x86_64-unknown-linux-musl。所选目标缺少 lib-base 包时会报错并提示应安装的归档；已安装 lib-gui 包时同时生成 GUI 库文档。已生成的文档按输入变化复用。

  3. 加入 PATH 
    # ~/.zshrc 或 ~/.bashrc
export PATH="$HOME/.scoop/bin:$PATH"

    Windows 手动安装时，在 PowerShell 中把各归档解压到 %USERPROFILE%\.scoop，运行 post-install（默认目标为 MSVC UCRT），并把 %USERPROFILE%\.scoop\bin 加入用户 PATH：

    New-Item -ItemType Directory -Force "$HOME/.scoop"
Get-ChildItem scoop-*.tar.xz | ForEach-Object { tar -xJf $_.FullName -C "$HOME/.scoop" }
& "$HOME/.scoop/post-install.ps1"
# 已安装 MinGW 目标的 lib-base 与 native 包时：
& "$HOME/.scoop/post-install.ps1" --target x86_64-w64-windows-llvm-mingw-ucrt
  4. 确认安装 
    $ scoop --version          # Windows：sco --version
scoop <version> (<revision>)

    scoop 会自动把自身所在的安装根作为 sysroot；如需使用其他位置，可设置 SCOOP_SYSROOT 或传入 --sysroot。

安装根的目录结构：

~/.scoop/
  VERSION
  post-install.sh       安装后准备入口，Windows 为 post-install.ps1
  bin/                  scoop（Windows 为 sco.exe）、scoopc、scoop-link、scoop-lsp、scoop-pm、
                        scoop-lldb、scoop-lldb-dap 及其他 scoop- 前缀的 LLVM 工具
  commands/             scoop-example 等外部子命令
  lib/<target-triple>/  预编译系统库 .slib、原生静态库与运行时（lib-base／lib-gui 包）
  libexec/llvm/         随包 Clang、LLD 等 LLVM 工具及其动态库
  libexec/lldb/         调试器配套 Python 与平台 helper
  include/              公开的 Scoop C 头文件
  src/                  全部内置 Cone 的源码与示例
  share/scoop/          toolchain.toml（工具包内容与目标信息）、离线示例索引与正文
  docs/                 安装后生成的标准库 API 文档，按目标区分
  tooling/              VS Code 扩展与 Scoop 编程 skill
从源码构建

Scoop 仍处于开发预览阶段。你也可以从 GitHub 仓库 构建完整工具包：先按脚本说明准备 Python 3.12+ 及开发文件、SWIG 4、Ninja、Rust、C/C++ 工具链、CMake、Make、Perl、Node.js 22.18+ 与 npm，再执行 python3 scripts/package_toolchain.py --jobs 6。归档生成在 tmp/dist 下。

第一个程序

新建 hello.scoop：

{{example hello nooutput}}

直接运行这个文件：

$ scoop run hello.scoop --release
Hello, Scoop!

单文件程序默认依赖 scoop.core 与 scoop.std，不读取旁边的 Cone.toml；编译产物放在当前目录的 target/ 下。--release 启用优化。建议总是用 -- 分隔 Scoop 选项与程序参数，例如 scoop run hello.scoop --release -- Ada；程序的 args[0L] 是启动路径，用户参数从 args[1L] 开始。

单文件依赖

单文件程序在文件头部用 //! dep: 声明额外依赖的精确坐标，从预编译产物中查找，例如使用 JSON 库。单文件入口不参与 PM 的版本求解；需要 Git/registry、源码依赖或 workspace 时使用 Cone 项目。

{{example json}}

文件首行也可以是 #! 解释器注释，因此 Scoop 文件能直接作为脚本执行：

#!/usr/bin/env -S scoop run --release
fun main() {
    println("I am a script")
}

创建项目

Scoop 的模块、包与发布单元叫做 Cone。用 scoop new 创建一个可执行 Cone：

$ scoop new --group dev.example hello
created hello
$ cd hello
$ scoop run --release
Hello, Scoop!

生成的结构如下：

hello/
  Cone.toml          Cone 清单
  src/main.scoop     生产源码
  tests/basic.scoop  测试源码（只在 scoop test 时编译）
src/main.scoop
package dev.example

fun main() {
    println(greeting())
}

fun greeting(): String = "Hello, Scoop!"
tests/basic.scoop
package dev.example

import scoop.test.*

@Test
private class BasicTests {
    @Test
    fun `greeting is ready`() {
        assertEquals("Hello, Scoop!", greeting())
    }
}
$ scoop test --release
hello
  dev.example.BasicTests [passed]
    greeting is ready (tests/basic.scoop:7:5) passed (4000 ns)
1 containers, 1 tests: 1 passed, 0 failed, 0 ignored, 0 not run

使用 --kind library 创建库 Cone，--no-tests 省略示例测试。

Cone.toml 与依赖

Cone 自身用完整 group:name:version 标识；依赖可以声明版本要求，由独立包管理器解析，再用 Cone.lock 固定精确版本与来源。下面是仅依赖内置库、可以直接使用的清单：

Cone.toml
schema = 1

[cone]
group = "dev.example"
name = "my-app"
version = "0.1.0"
kind = "executable"

[dependencies]
"scoop:scoop.std" = "=0.1.0"
"scoop:scoop.json" = "=0.1.0"

[test-dependencies]
"scoop:scoop.test" = "=0.1.0"

"1.4.0" 和 "^1.4.0" 都表示 >=1.4.0, <2.0.0；"=1.4.0" 才是精确版本。~1.4.2 和比较项交集也可使用；0.x 的兼容范围按首个非零版本段收窄。不能写 latest、通配符或省略版本段。

在 [dependencies] 中还可以按实际来源加入以下条目；示例目录、仓库和 registry 地址须替换成自己的输入：

"dev.example:util" = { version = "0.2.0", path = "../util" }
"org.example:http" = { version = "1.2.0", github = "example/http", tag = "v1.2.0" }
"org.example:json" = { version = "1.4.0", registry = "https://packages.example.org/" }
"org.acme:codec" = { version = "=1.0.0", artifact = "../artifacts/codec.slib" }
  • path 指向另一个源码 Cone，scoop 会一并构建；
  • github/git 指定 Git 来源，branch/tag/rev 选择引用，lock 固定实际 commit；
  • registry 指向静态 HTTP(S) registry；PM 选择版本、下载源码后交给构建工具；
  • artifact 指向预编译的 .slib 产物；
  • 未指定来源的 scoop group 使用 sysroot；其他 group 使用已配置的默认 registry，没有默认值就报错；
  • [test-dependencies] 只参与测试构建，不进入生产产物。

普通构建会自动解析并生成或更新必要的 lock 记录，优先保留相容的已有选择。可以把 Cone.lock 提交到版本库，在 CI 使用 --locked，或在依赖已准备时用 --frozen 同时禁止联网：

$ scoop pm resolve
$ scoop pm deps
$ scoop build --release --locked
$ scoop pm update

Git/registry 源码默认缓存在 ~/.scoop/packages/。多 Cone 项目可以使用 [workspace]，通过 -p group:name 选择成员，或用 scoop build --workspace / scoop test --workspace 处理全部成员；run 必须选中唯一可执行 Cone。规则见包管理规范。维护 registry 的步骤见发布指南；目前已交付消费端，打包与索引维护命令仍属后续计划。

Cone 还可以携带 C/C++ 源码与原生系统库，用于编写 FFI 绑定，详见参考文档的原生互操作一章。

命令速查

命令作用
scoop new <path> --group <g>用固定模板创建可执行或库 Cone
scoop pm <command>管理 workspace、依赖与锁文件；支持 add/remove、resolve/fetch/update、deps 等
scoop build [root]从 Cone 或单个源文件构建可执行文件或库；-o 指定输出，--emit ast|hir|mir|lir|all --dump-dir DIR 导出中间表示
scoop run [root] [args…]构建并运行可执行文件，继承调用者的环境变量和标准输入输出
scoop test构建并运行当前 Cone 的测试
scoop fmt [inputs…]格式化 Cone 或指定源码；--check 只报告格式差异
scoop check [root]完成前端检查，不生成根 Cone 的机器产物；--tests 检查测试用途
scoop doc [roots…]从文档注释生成离线 API 文档站点
scoop link不编译源码，只链接已有产物
scoop clean [root]移除选定 target 目录中的所有 profile 与构建缓存
scoop example [topic]查询离线示例；支持 --list 与 --search
scoop <other>运行 <sysroot>/commands/scoop-<other> 外部子命令

常用选项：--release（优化构建）、--target <triple>（交叉目标）、--target-dir（输出目录）、-j（并发编译进程数）、--message-format json（机器可读诊断）。

编辑器支持

工具包附带 VS Code 扩展，提供 Tree-sitter 语法高亮、折叠、缩进，以及通过 scoop-lsp 提供的诊断、补全、悬停文档、签名帮助、跳转、引用、重命名和快速修复：

$ code --install-extension ~/.scoop/tooling/scoop-language-support-*.vsix

扩展会依次查找 scoop.server.path 设置、~/.scoop/bin/scoop-lsp 与 PATH 中的 scoop-lsp。Tree-sitter 语法包（tree-sitter-scoop）也可以单独用于其他支持 Tree-sitter 的编辑器。

编辑器消费已有的锁定依赖，不自动更新版本或下载源码。缺少 lock 或依赖时，在项目目录运行 scoop pm resolve 或 scoop pm fetch，再继续分析。

源码调试

工具包附带 scoop-lldb 与 scoop-lldb-dap（带 scoop- 前缀，可与其他 LLVM 安装共存于 PATH）。在 VS Code 中按 F5 选择 Scoop，或运行 Scoop: Debug Current File，可自动构建并启动调试；也支持调试测试和附加现有进程。

$ scoop build --release --debug-info full

调试文件随程序输出：macOS 使用 .dSYM，Linux 使用 .debug，Windows 使用相邻的 .pdb。debug 构建默认包含完整调试信息，release 默认不包含；异常与 trap 可以显示物理栈及源码位置。当前不提供完整 Scoop 表达式求值或协程逻辑栈，配置方法见调试说明。
